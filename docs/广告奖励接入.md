# 钱包与激励视频

## 已确认规则

- 余额单位显示元 / ￥，明确为虚拟余额，无真实支付、充值、转账或提现。
- 新用户 100 元，每日补给 20 元维持原规则。
- 每天完整观看前三次广告分别 +50、+100、+200 元，每日最多 350 元广告奖励。北京时间自然日重置。
- 广告中途关闭、无广告、加载失败、超时均不发奖、不扣奖励次数；重复回调只处理一次。
- 用户已决定取消分享奖励，不实现分享加钱接口或演示。
- 购买一包烟增加 20 支，开始体验消耗 1 支。原创雨后、夜班仍分别 20 / 30 元，基础留白免费不限量。旧余额和旧库存原样保留，不因每包数量更新而补发。

## 开发演示

默认前端本地模式无需广告位。在钱包点击“模拟观看”，弹窗明确说明不播放真实广告，可选“模拟看完”或“中途关闭”。奖励状态与流水保存在本地存档。

API 开发模式需要后端配置 `REWARD_DEMO=true`。生产环境 `NODE_ENV=production` 拒绝该配置。未配置广告位且未显式启用演示的后端返回 unavailable，前端禁用观看按钮。不要将本地模拟包作为正式发布包。

## 接入真实广告

1. 在自己的小程序账号取得有效的激励视频广告位。
2. 后端配置 `WECHAT_REWARDED_AD_UNIT_ID=adunit-实际ID`，关闭 `REWARD_DEMO`。广告位 ID 非密钥，随 bootstrap 下发。
3. 前端使用 API 模式构建，填写实际 HTTPS 接口地址。
4. `services/rewarded-ad.ts` 调用 wx.createRewardedVideoAd、load、show，只有 onClose 的 isEnded 明确为 true 才进入领取流程。
5. 在微信开发者工具和真机验证广告资格、广告位、无填充、完整观看、中途退出、弱网与切后台。当前没有真实广告位，以上真机验收尚未执行。

微信参考：[完整观看回调](https://developers.weixin.qq.com/miniprogram/dev/api/ad/RewardedVideoAd.onClose.html)、[创建激励视频](https://developers.weixin.qq.com/miniprogram/dev/api/ad/wx.createRewardedVideoAd.html)、[腾讯广告操作指引](https://training.tencentads.com/uploads/202111/WKng9NuB_mvnNBw.pdf)。实现同时对照项目已有微信 API 类型定义。

## 发奖与重试

观看前向后端申请 ticket，金额由服务端计算。每账号同一时间复用一个有效待完成机会。完整观看后先将 ticket ID 存为“待领取”，再调用发奖接口；发奖失败可重试，成功后清理待领取标记。关闭页面会解除广告事件监听，取消尚未完成的本次观看。

服务端按玩家行锁串行处理，防止并发重复加钱；已领取 ticket 重试返回原金额。未完成 ticket 30 分钟有效且不得跨北京时间日期。接口拒绝客户端指定奖励金额、非本人 ticket 和每日第四次奖励。

## 验证范围与上线限制

单元测试覆盖 SDK 回调桩、未看完、加载失败、超时、重复回调、页面退出、失败后重试、跨日重置、三次封顶、账号隔离与并发幂等。真实广告、广告平台收益及线上风控尚未验证。

**普通 onClose 回调不是广告平台的服务端验真凭证。** 现有 ticket 机制能控制账户归属、额度和重复发放，不能阻止修改过的客户端直接模拟完整观看后请求领取。不能把客户端回调当作“服务端已经验证观看”。正式运营前，需结合实际账号可用的广告平台验真能力与反滥用措施补齐并验收；不能据此承诺无作弊风险。
